Understanding Accessibility

Different users have different needs.

Accessible design considers how people with different abilities interact with digital products.

01

Visual

Users may need readable text, strong contrast, alternative text, or screen-reader-friendly content.

02

Hearing

Audio and video information should also be available through captions, transcripts, or visual alternatives.

03

Motor

Some users rely on keyboards or other input methods instead of precise mouse or touch movements.

04

Cognitive

Clear language, predictable layouts, and understandable feedback can make interfaces easier to use.

01

Visual Accessibility

Images need meaningful descriptions.

Users who cannot see an image may rely on alternative text or other descriptions to understand its meaning.

▧ Sample Image Student using a laptop

Image description

“A student sitting at a desk while using a laptop to access an online learning website.”

Why it matters:

A meaningful description communicates important visual information to users who cannot see the image.

02

Hearing Accessibility

Audio information needs alternatives.

Captions and transcripts allow information to be understood even when audio cannot be heard.

▶

Campus Announcement

Motor Accessibility

Keyboard navigation and visible focus.

Some users navigate websites without a mouse. Keyboard controls should work, and the currently focused element should be easy to identify.

04

Cognitive Accessibility

Clear messages are easier to understand.

Error messages should explain what happened and what the user can do next.

Poor Example

Error 0x004-A7

Request validation exception. Invalid authentication input parameter.

Better Example

We couldn't sign you in.

Check your email and password, then try again. If you forgot your password, you can reset it.

05

Motion Accessibility

Not every interface needs strong movement.

Some users may find unnecessary movement distracting or uncomfortable. Reduced motion can keep the same information while limiting animation.

06

Ethical Accessibility

Accessibility is also about responsible design.

Ethical design considers inclusion, fairness, independence, privacy, and equal opportunity.

Explore the scenarios below and compare a poor approach with a more responsible design decision.

01

Inclusion

Scenario

A university website publishes important information only inside images.

Poor Approach

Important text exists only inside the image.

Better Approach

Provide the same information as readable webpage text.

Inclusion means designing so that more people can access the same information and services.
02

Fairness

Scenario

An online activity can only be completed using precise mouse movements.

Poor Approach

Require every user to interact in exactly the same way.

Better Approach

Support keyboard interaction and other input methods.

Fairness does not always mean giving everyone the exact same interaction. Users may need different ways to accomplish the same task.
03

Respect & Independence

Scenario

A user needs assistance every time they want to complete a basic online task.

Poor Approach

Assume another person will always help the user.

Better Approach

Design the task so users can complete it independently when possible.

Accessible design should support independence and avoid unnecessary barriers.
04

Privacy

Scenario

A website asks users to publicly explain their disability before providing an accessibility option.

Poor Approach

Require unnecessary personal information.

Better Approach

Allow accessibility preferences without requiring sensitive explanations.

Accessibility should not require users to reveal unnecessary personal information.
05

Equal Opportunity

Scenario

An online examination contains videos with important instructions but no captions or transcript.

Poor Approach

Provide important instructions only through audio.

Better Approach

Provide captions or a text transcript containing the same information.

Users should have a fair opportunity to receive important information and complete digital activities.

Accessibility Principles

WCAG and the POUR Principles

WCAG organizes many accessibility recommendations around four major principles: Perceivable, Operable, Understandable, and Robust.

P

Perceivable

Information should be presented in ways users can perceive.

  • Text alternatives for images
  • Captions for audio and video
  • Readable text and contrast
O

Operable

Users should be able to operate interface controls using appropriate input methods.

  • Keyboard-accessible controls
  • Visible keyboard focus
  • Usable navigation
U

Understandable

Content and interactions should be clear and predictable.

  • Simple instructions
  • Clear error messages
  • Consistent navigation
R

Robust

Content should work reliably with different technologies and assistive tools.

  • Semantic HTML
  • Correct labels
  • Compatible controls

Design for Mobile Devices

Good interfaces should work on smaller screens.

Mobile design requires readable content, simple navigation, appropriate touch controls, responsive layouts, and clear system feedback.

01

Responsive Layout

Content should adapt to different screen sizes instead of forcing users to zoom or scroll horizontally.

02

Touch-Friendly Controls

Buttons and interactive elements should provide enough space for comfortable touch interaction.

03

Clear Navigation

Mobile navigation should remain simple, understandable, and easy to access.

04

System Feedback

Users should receive clear feedback after actions such as submitting, saving, or loading information.

Responsive Example

Resize your browser window.

Make the browser narrower and observe how the navigation, cards, text, and sections reorganize themselves for smaller screens.

Tip: On a computer, slowly drag the edge of your browser window inward.
